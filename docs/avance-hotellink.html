    Cómo se calculó el porcentaje
    • Son requisitos tomados de los alcances, el manual de usuario, el manual técnico y el diccionario de datos.
    • Cada uno se puntúa en cuatro capas: datos (20 %), lógica (35 %), pantalla React (30 %) y pruebas (15 %). Una capa vale 0, 0.5 o 1, y las que no aplican se excluyen.
    • Lo que solo funciona en Blade vale 0.5 en lógica, porque el manual fija React y la API como destino.
    • El peso de cada requisito (1 a 5) es una estimación de esfuerzo y criticidad. Mide trabajo pendiente, no líneas de código, así que el resultado es orientativo.
    • «Desarrollado» significa que datos, lógica y pantalla están completos; aun así puede faltarle pruebas.
    • Verificado el 15 de noviembre: 292 pruebas en verde sobre SQLite (2 997 comprobaciones). Bajaron de 309 porque se eliminaron las pruebas del panel Blade retirado. El ciclo de recepción se recorrió en Chrome el 7 de noviembre; reportes, valoraciones, respaldos y el portal bilingüe se verificaron solo por código y pruebas de API, no en el navegador.
